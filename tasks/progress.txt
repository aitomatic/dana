## Codebase Patterns
- Notifiable protocol: Extend `Notifiable` ABC from `dana.common.protocols.notifiable`, implement `notify(self, notifier: object, message: DictParams) -> None`
- DictParams is `dict[str, Any]` from `dana.common.protocols.types`
- Broadcast keys used by agents: `trace_percepts`, `trace_thoughts`, `trace_outputs`, `trace_learning`, `workflow_progress`, `skill_progress`
- Tests live in `dana_agent/tests/` with structure mirroring source (e.g., `tests/cli/` for `dana/cli/`)
- Use `uv run pytest` and `uv run ruff check` and `uv run mypy --ignore-missing-imports` for quality checks
- mypy requires generic type parameters (e.g., `list[Any]` not bare `list`)
- ThoughtLogger in `dana/apps/dana/thought_logger.py` is the reference Notifiable implementation
- Agent properties available via getattr: `object_id`, `agent_type`
- `rich` is available as a transitive dependency (not in pyproject.toml directly)
- ruff enforces import sorting (`isort`-style) - run `uv run ruff check --fix` after modifying `__init__.py` imports
- Stub handler methods with unused params are fine for Pyright warnings - they'll be filled in later stories
- `rich.spinner.Spinner.text` returns `rich.text.Text` (not `str`) - track text as plain string separately for testability
- Components package lives at `dana/cli/components/` - each component in its own file, exported from `__init__.py`
- `rich.live.Live` manages flicker-free updates: `_ensure_live()` to start, `_stop_live()` to teardown, `_refresh_display()` to update
- Mock `_ensure_live`, `_stop_live`, `_refresh_display` in tests to avoid terminal output while testing handler logic
- Broadcast data: `trace_thoughts` has `done` (bool), `response` (str), `tool_calls` (list[dict]), `reasoning` (str), `todo_list` (list)
- Broadcast data: `trace_outputs` has `tool_calls` (list[dict]), `tool_results` (list[dict])
- Broadcast data: `trace_percepts` has `caller_message` (str), `perception` (str)
- Tool call dict structure: `{"function": "tool_name", "arguments": {...}}`
- `rich.panel.Panel.renderable` provides body content, `str(panel.title)` for title text in test assertions
- Tool type classification in `ToolCardComponent._classify_tool()` - extend for new tool types
- Tool card integration: `_handle_think()` queues tool cards to `_pending_tool_cards`, `_handle_act()` and `done=True` flush them via `_flush_tool_cards()`
- `_flush_tool_cards()` temporarily stops Live, prints panels via `console.print()`, then restarts Live - cards persist in terminal history
- Use `patch.object(renderer.console, "print")` with `side_effect=lambda p: printed_panels.append(p)` to capture printed Panels in tests
- StreamDisplayComponent returns `rich.text.Text` renderables - no Live context dependency, compose into Group for Live display
- StreamDisplayComponent integration: `_handle_think()` streams response text (non-done), `_handle_see()` clears buffer for new STAR loop
- `_refresh_display()` composes spinner + stream display + status line into `Group()` for Live - all visible simultaneously
- Agent model: extract from `notifier.llm_client.model` with fallback to `notifier._llm_config["model"]`
- Agent turn: `notifier._star_loop_count` (private int), `notifier.max_turns` (public int)
- Subagent detection: track agent_id changes with `_agent_stack` - push parent on new ID, pop on known ID return
- `rich.table.Table` stores cells in columns, NOT rows: access via `table.columns[col_index]._cells[row_index]`, NOT `table.rows[row_index]._cells[col_index]`
- `_refresh_display()` render order: spinner → stream text → progress tracker → status line (top to bottom)
- Use `list[RenderableType]` (from `rich.console`) when renderables list needs to hold mixed types (Text, Table, etc.)
- ResultPanelComponent: stores state (tool_name, output, exit_code, is_recent), renders as Panel with collapse/expand
- Recent panels: `border_style="cyan"`, historical panels: `border_style="dim"` for visual distinction
- `Panel.border_style` is readable for test assertions
- Broadcast data: `trace_outputs.tool_results` is `list[dict]` with keys: `function`/`tool` (name), `output` (str), `exit_code` (int)
- Result panel lifecycle: created in `_handle_act()` (is_recent=True) → transitioned in `_handle_see()` (is_recent=False, moved to historical)
- `_refresh_display()` render order: spinner → stream → historical results (collapsed) → current results (interactive) → progress → status
- Thread safety: `notify()` acquires `_lock` at top level (all handlers run under lock); keyboard nav methods (`select_up`, `select_down`, `toggle_expand`) acquire lock independently
- `threading.Lock()` returns an object, not a type - can't use `isinstance()` for type checking
- Terminal capability detection: `console.color_system is not None` for color support, `console.width` for terminal width
- No-color fallback: `_has_color=False` skips `_ensure_live()`, prints plain text via `console.print()` with phase prefix (e.g., `[SEE]`, `[THINK]`, `[ACT]`)
- Tool cards in no-color mode: print `-> tool_name: key=value` instead of Panel rendering
- SIGWINCH handler: install in `_install_resize_handler()`, chain to previous handler with `is` comparison (not `==`) for SIG_DFL/SIG_IGN
- Tests with `Console(force_terminal=False)` have `color_system=None` → triggers no-color path; use `Console(force_terminal=True)` for tests that expect rich/color behavior
- `signal.signal()` with MagicMock as handler doesn't work: Python converts MagicMock via `__int__()` → use real functions as signal handler mocks in tests
- `_truncate_for_width()` accounts for panel borders (6 chars) and has a minimum of 10 chars
- Integration testing: extend `Notifier` class directly (not mock) to test real `with_notifiable()` + `broadcast()` flow
- ThoughtLogger(verbose=False, show_tool_calls=False) to silence output during integration tests

## 2026-02-06 - US-016
- Added thread safety to RichCLIRenderer via `threading.Lock`
- Lock protects all state mutations: `notify()` wraps entire handler dispatch, `select_up()`/`select_down()`/`toggle_expand()` each acquire lock
- `_lock` initialized in constructor as `threading.Lock()`
- Lock scope: `notify()` acquires lock once at top level, so all handlers (`_handle_see`, `_handle_think`, `_handle_act`, etc.) run under lock without needing nested locks
- Keyboard navigation methods acquire lock independently since they're called from different threads (UI thread)
- Created `tests/cli/test_thread_safety.py` with 12 tests across 6 test classes
- Test classes: TestLockExists, TestConcurrentBroadcasts, TestConcurrentKeyboardNavigation, TestConcurrentBroadcastsWithKeyboard, TestLockSerializesBroadcasts, TestNoDataCorruptionUnderLoad

- Files changed: `dana/cli/rich_cli_renderer.py`, `tests/cli/test_thread_safety.py`
- **Learnings for future iterations:**
  - `threading.Lock()` returns an object, not a type - `isinstance(lock, threading.Lock)` fails with TypeError; use `hasattr` checks instead
  - Lock at `notify()` level is sufficient - handlers are always called within notify, so no nested locking needed
  - `threading.Barrier(N)` is excellent for test contention - all threads wait until N arrive, then release simultaneously
  - Keyboard navigation methods need independent locks because they're called from a different thread (UI/input thread) than broadcasts (agent thread)
  - Python's GIL doesn't prevent all race conditions - list mutations (`append`, `extend`, `clear`) can still interleave between threads at the bytecode level

- Added graceful degradation for limited terminals to RichCLIRenderer
- Terminal capability detection: `_has_color` from `console.color_system`, `is_narrow` from `console.width < 80`, `terminal_width` property
- No-color fallback: handlers print plain text with phase prefixes `[SEE]`, `[THINK]`, `[ACT]` instead of using Live context
- Tool cards in no-color mode: print `-> tool_name: key=value` instead of rich Panel rendering
- Narrow terminal: `_truncate_for_width()` truncates text with ellipsis, accounts for panel borders (6 chars), minimum 10 chars
- SIGWINCH handler: `_install_resize_handler()` installs signal handler that calls `_refresh_display()` on resize, chains to previous handler
- Handler chains using `is` comparison (not `==`) for SIG_DFL/SIG_IGN to avoid MagicMock `__int__()` confusion
- Silently skips handler installation on Windows (no SIGWINCH) or non-main threads (ValueError from signal.signal)
- Updated existing test files to use `Console(force_terminal=True)` instead of `Console(force_terminal=False)` to preserve rich behavior in tests
- Created `tests/cli/test_graceful_degradation.py` with 36 tests across 7 test classes
- Total test count: 373 tests across all CLI test files
- Files changed: `dana/cli/rich_cli_renderer.py`, `tests/cli/test_graceful_degradation.py`, `tests/cli/test_rich_cli_renderer.py`, `tests/cli/test_keyboard_navigation.py`, `tests/cli/test_thread_safety.py`
- **Learnings for future iterations:**
  - `Console(force_terminal=False)` makes `color_system` return `None` → triggers no-color path; always use `Console(force_terminal=True)` for tests expecting rich behavior
  - Python's `signal.signal()` converts MagicMock via `__int__()` → use real functions as signal handler mocks
  - Use `is` (identity) not `==` (equality) when comparing signal handlers to SIG_DFL/SIG_IGN constants
  - `signal.signal()` raises ValueError from non-main threads → wrap in try/except
  - SIGWINCH not available on Windows → guard with `hasattr(signal, "SIGWINCH")`
